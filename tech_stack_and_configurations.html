AI Hallucination Detection & Verification System

Complete Technical Stack, Configuration Specification & System Architecture Guide
Author / System: Anti-Hallucination Engineering Platform Frameworks: FastAPI, Python 3.11+, Pydantic v2, SQLite Status: Production Ready (Local & Cloud)

This document serves as the official technical manual for the AI Hallucination Detection and Verification System. Rather than relying on superficial keyword matching or vulnerable single-prompt self-consistency loops, the platform breaks AI responses into atomic, typed propositions, conducts independent evidence retrieval, scores domain credibility, detects fine-grained contradictions (temporal, numerical, entity), subjects verdicts to an adversarial critic, and computes deterministic reliability metrics.

1. System Architecture & Multi-Agent Hierarchy

The verification pipeline executes asynchronously across 6 specialized agents:

USER INPUT (Question or Pasted Answer)
   │
   ▼
AGENT 1: ANSWER GENERATOR (LLM Generation or Passthrough User Text)
   │
   ▼
AGENT 2: ATOMIC CLAIM EXTRACTOR (Syntactic & Semantic Decomposition into 12+ Typed Claims)
   │
   ▼
CLAIM NORMALIZER & QUERY PLANNER (Targeted Search Queries & Entity Anchoring)
   │
   ▼
AGENT 3: EVIDENCE RETRIEVER (Wikipedia REST API + DuckDuckGo Web Search + HTML Chunk Scraper)
   │
   ▼
SOURCE QUALITY EVALUATOR (Explainable 0–100 Rubric: Provenance, Recency, Semantic Alignment)
   │
   ▼
AGENT 4: ZERO-TRUST VERIFIER (Temporal, Numerical & Inter-Source NLI Verification)
   │
   ▼
AGENT 5: ADVERSARIAL CRITIC (Catches Confirmation Bias, Weak Provenance & Uncited Claims)
   │
   ▼
AGENT 6: HALLUCINATION SCORING ENGINE (Harmonic Reliability 0–100 & Hallucination Risk %)
   │
   ▼
SQLITE AUDIT PERSISTENCE & INTERACTIVE REAL-TIME DASHBOARD UI
Zero-Trust Verification Principle

An absence of evidence strictly yields UNVERIFIED—it is never guessed as false or assumed true. Claims are grounded exclusively in retrieved evidence tokens with verifiable citations.

Offline & Zero-Cost Operation

When all LLM API keys are unset, the system functions seamlessly in hybrid heuristic mode. It utilizes the Wikipedia REST API and DuckDuckGo search without incurring any third-party API fees.

4. Scoring Formulas, Rubric & Database Schema

4.1 Source Quality Scoring Rubric (0–100)

Source Category Base Score Domain Patterns & Qualification Criteria
Government & Official 92.0 .gov, .mil, .gov.uk, .europa.eu, who.int, nasa.gov. Primary official provenance.
Academic & Peer-Reviewed 88.0 .edu, arxiv.org, nature.com, science.org, ncbi.nlm.nih.gov, ieee.org.
Tier-1 Journalism 80.0 reuters.com, apnews.com, bbc.com, nytimes.com, wsj.com, theguardian.com.
Curated References 75.0 wikipedia.org, britannica.com, plato.stanford.edu, worldcat.org.
General Web Public 55.0 Standard verified blogs, corporate publications, documentation portals.
User-Generated Content 25.0 reddit.com, quora.com, twitter.com, x.com, medium.com, wordpress.com.

Relevance Adjustment: Score = BaseScore + (Relevance - 0.5) * 15.0 (clamped to [5.0, 99.0]).

4.2 Reliability & Risk Formulation

Overall Reliability (0–100)

Weighted harmonic aggregation across factual claims:

Reliability = (∑ W_i × VerdictScore_i) / (∑ W_i) × 100
  • W_i = Importance × Confidence
  • Supported: 1.0 × min(1.0, max(0.6, SQ / 85.0))
  • Partially Supported: 0.65 × min(1.0, max(0.6, SQ / 85.0))
  • Unverified: 0.35 (uncertainty floor) | Contradicted: 0.00

Hallucination Risk (%)

Quantifies verified errors & epistemic uncertainty:

Risk = (∑ W_i × RiskFactor_i) / (∑ W_i) × 100
  • Contradicted: 1.00 (confirmed hallucination)
  • Unverified: 0.50 (epistemic uncertainty penalty)
  • Partially Supported: 0.35 (minor factual deviation)
  • Supported: 0.00

4.3 Database Schema (SQLite)

CREATE TABLE reports (
    report_id TEXT PRIMARY KEY, question TEXT NOT NULL, answer TEXT NOT NULL,
    model_name TEXT, created_at TEXT NOT NULL, overall_reliability REAL,
    hallucination_risk REAL, summary_counts TEXT, score_breakdown TEXT, explanation TEXT, raw_json TEXT
);
CREATE TABLE claims (
    claim_id TEXT NOT NULL, report_id TEXT NOT NULL, claim_text TEXT NOT NULL,
    claim_type TEXT NOT NULL, importance REAL, requires_verification INTEGER,
    verdict TEXT, confidence REAL, PRIMARY KEY (report_id, claim_id),
    FOREIGN KEY (report_id) REFERENCES reports (report_id) ON DELETE CASCADE
);
CREATE TABLE evidence (
    evidence_id TEXT NOT NULL, report_id TEXT NOT NULL, claim_id TEXT NOT NULL,
    source_title TEXT, source_url TEXT, source_domain TEXT, source_type TEXT,
    snippet TEXT, relevance REAL, source_quality_score REAL, PRIMARY KEY (report_id, evidence_id),
    FOREIGN KEY (report_id) REFERENCES reports (report_id) ON DELETE CASCADE
);
